# 职业咨询交互回归验收清单（平台无关）

本清单测试**对话行为**，不替代就业市场事实研究和职业建议审查。所有情境是匿名化/合成的跨平台输入，不包含任何具体平台的事故来源；**不要求使用平台专属工具或 API**。

## 执行方法

1. 从全新会话启动安装好的 `SKILL.md`，逐条输入 `interaction_cases.json` 的 `context` 与 `prompt`（可通过模拟上轮对话补充上下文）。
2. 检查实际输出是否满足 `expected`、有没有触发 `fail_if`；按 **通过 / 部分通过 / 失败 / 未测试** 记录，保留去标识化对话文本或截图。
3. 依序测试“首次请求 → 用户回答 → 后续推进”，尤其观察是否重复索取已知信息，是否连续两轮只有问卷没有分析。
4. 平台有原生选择控件时，验证其只服务有限选项；平台没有时，验证能用自然语言等效推进。不要将“用了控件”本身当作通过条件。
5. 工具暂不可用时，须说明无法核实哪些事实，并给出可执行的条件性下一步；不得声称已联网或已联系招聘方。

## 用例清单

| ID | 场景 | 主要验收点 |
| --- | --- | --- |
| INT-01 | 选择职业咨询类型后 | 不重启完整接案问卷，不展示长篇服务流程 |
| INT-02 | 需要讲述复杂经历 | 开放式提问优先，不强制选择卡 |
| INT-03 | 计算现金跑道 | 采集原始 C/E/I，工作流自己计算 |
| INT-04 | 多项职业价值都重要 | 不宣称无效，只在有真实冲突时细问 |
| INT-05 | 明确要求跳过提问 | 继续研究可做事项，不编造关键数据 |
| INT-06 | 目标城市与职业已知 | 不重复确认已知事实 |
| INT-07 | 回答一个关键问题后 | 当轮有实质推进，不能接二连三只问问题 |
| INT-08 | 无选择控件 | 自然语言降级，不编造工具调用 |
| INT-09 | 高额培训与硬门槛 | 不因简短输出而省略重大风险 |
| INT-10 | “年底看到结果”含糊 | 可先提供可逆方案，必要时只澄清结果定义 |

## 与职业咨询能力测试的区别

本清单聚焦对话界面；更高层的研究、计算与建议质量须另跑 `tests/BEHAVIOR_EVALUATION.md` 的 `E2E-xx` 场景。所有手工分数默认**未测试**，绝不能用单元测试通过替代。
