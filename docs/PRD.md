# JobSniper PRD

## 1. 产品概述

JobSniper 是一个面向本地求职情报与职业战略决策的 MCP Server 及 Agent 工作台。它不仅让 Codex、Claude Desktop 等 AI Client 可以通过统一 MCP 接口读取岗位知识库、启动招聘平台采集、归档采集产物、维护用户画像，更致力于构建**「环境（Environment）- 岗位（Position）- 用户（User）」三位一体的立体情报体系**，为职业规划、岗位推荐、简历定制和面试模拟提供真实、可靠、可验证的数据与决策底座。

当前版本已打通智联招聘（Zhilian）与 BOSS 直聘（Boss Zhipin）两条微观岗位情报链路（job menu 发现、职业关键词岗位列表采集、单岗位详情采集、Downloads 产物归档、岗位详情检索和用户画像更新），并正在向包含**宏观/中观市场与行业情报层（`markets`）**的三维决策架构演进。

## 2. 核心设计哲学：三位一体与双向适配

### 2.1 告别“二元平面匹配”缺陷
传统求职工具仅依赖**「用户简历/自述（User）↔ 岗位 JD（Position）」**的二元平面比对（如单纯的 ATS 关键词覆盖率或文本余弦相似度）。这种静态模式在真实职场中极易导致三大系统性失真：
1. **假性匹配陷阱（Ghost Matching）**：简历与 JD 文本高度吻合，但无法识别目标企业亏损裁员、业务线收缩、HC 冻结或虚假挂岗（Ghost Jobs）。
2. **考核错位与冒名顶替陷阱**：将 HR 堆砌的“愿望清单式 JD”奉为圭臬，误导求职者去硬闯学历/算子推导壁垒森严的红海赛道，忽略自身真正的复合竞争优势。
3. **生态位盲区（Blind Track）**：看不见行业转型期的人才供需断层（如传统教培老师不懂 AI 工程、纯互联网 PM 不懂一线教学心智的断层），错失降维打击的高胜率赛道。

### 2.2 「环境 - 岗位 - 用户」三位一体立体情报体系
JobSniper 引入**第三维：全景社会、市场与行业环境情报（Environment）**，形成三维空间定位：
- **环境层（Environment / 宏观与中观五维全景）**：
  1. **人口学与人才供给统计**：高校（本科、硕士、博士）历年在校生规模、同年应届毕业人数与历史变化趋势（学历通胀与竞争拥挤度测算）、社会就业/失业人口统计，以及学龄/适龄消费人口波峰波谷推移；
  2. **宏观政经与政策制度**：国内经济发展周期、全球经济走势、国际政治经济关系（算力博弈、跨国出海合规与地缘风险）、国家与地方政府产业政策（如“人工智能+”、教育白名单与拔尖人才政策）；
  3. **行业结构与市场行情**：产业链上下游结构、行业集中度、生命周期阶段、真实 HC 供求景气度与结构性人才断层；
  4. **企业财报与经营基本面**：上市公司财报、营收增速、现金流健康度、核心造血业务与战略转向；
  5. **学术前沿与技术演进**：核心顶会论文（Papers）、前沿算法工程化落地瓶颈、生产力范式转移。
- **岗位层（Position / 微观组织）**：招聘平台实时 JD、企业业务落地真实痛点、团队人才结构、实际面试考核潜规则、晋升通道与薪酬带宽。
- **用户层（User / 个体资产与边界）**：真实能力底盘、工程/业务流利度（如 Vibe Coding 独立交付闭环）、可迁移资产、财务现金跑道（Runway）、心理承压与人际消耗偏好。

### 2.3 双向价值适配原则
JobSniper 的一切推荐、简历修缮、面试辅导与职业咨询，均围绕**双向适配**展开：
1. **用户个人价值 ➔ 社会环境与行业市场需求适配（供给击穿需求）**：不削足适履迎合死板 JD，而是顺应行业生产力演进趋势，用求职者独特的复合能力击穿企业最迫切的业务痛点。
2. **社会环境与行业市场价值 ➔ 用户个人需求适配（环境滋养个体）**：评估目标行业与组织形态（大厂体系 vs 极客小团队、跨部门拉通 vs 独立闭环交付）能否提供匹配用户心理舒适区、财务安全底线与长期复利增长的生存土壤。

## 3. 目标用户

- **求职者 / 职业转型者**：维护个人能力事实库、岗位知识库与行业情报库，获取有真实市场证据支撑的职业定位、简历定制与面试策略。
- **AI Agent / 职业咨询师**：通过 MCP 工具与领域技能（Skills）调取三维情报，执行“事实—假设—市场核验—决策—行动—复盘”闭环。
- **后续求职工作流**：基于「环境-岗位-用户」三维底座驱动岗位推荐（`job-recommend`）、简历定制（`resume-tailor`）、ATS 诊断（`resume-matcher`）、深度访谈（`career-interview`）与职业咨询（`career-counseling`）。

## 4. 版本范围与演进路线

### 4.1 当前 MVP 已包含（V1.x）

- FastMCP stdio 服务入口。
- MCP Resource：读取当前用户画像（`jobsniper://persona`）。
- MCP Resource：按平台和自然嵌套路径读取岗位详情 Markdown。
- MCP Tool：按文件名搜索岗位详情。
- MCP Tool：以统一 `platform` 参数（`zhilian` / `boss`）启动 job menu、job list、job detail 三类采集。
- BOSS 直聘采集闭环：列表滚动采集、详情页采集、详情与公司信息合并归档。
- MCP Tool：归档 Joblens 下载产物到 `storage_layer/positions`。
- MCP Tool：更新用户画像技能置信度。
- Chrome 扩展 Joblens：负责浏览器内页面访问、队列消费和数据导出。
- 仓库内监视脚本：根据 results JSONL 判断完成、失败、重试和归档。
- 核心求职技能包（Skills）：`career-counseling`、`career-interview`、`job-recommend`、`resume-matcher`、`resume-tailor`。

### 4.2 立体情报体系升级范围（V2.0 演进规划）

> 详细架构规范参见 [`docs/TRINITY_INTELLIGENCE_ARCHITECTURE.md`](TRINITY_INTELLIGENCE_ARCHITECTURE.md)。

- **存储层扩容（`storage_layer/markets/`）**：新增人口学与高校/就业统计（`demographics/`）、宏观政经与国家政策（`macro_policy/`）、行业结构与市场行情雷达（`industries/`）、头部企业财报/业务健康度档案（`companies/`）、学术论文与技术范式专题（`papers_and_trends/`）五大维度的标准化存储与索引。
- **多模态权威媒介情报采集链路**：融合**统计公报（教育部/统计局/人社部）、政府政策公文、企业财报、学术论文（Papers）、深度财经科技新闻与券商研报**五大媒介源，沉淀可复核的环境层证据。
- **MCP 工具与资源扩展**：支持读取与更新市场情报库、查询目标公司经营健康度与赛道景气度。
- **全链路 Skills 三维升级**：
  - 在职业定位与推荐中强制引入**行业景气度、企业财报健康度与人才断层红利**加权；
  - 在简历定制与模拟面试中前置注入**企业当季核心业务痛点**与**岗位真实考核边界**。

### 4.3 暂不包含

- 本地配置文件支持（`.env` / `jobsniper.local.json`）。
- Joblens 扩展队列路径配置化（扩展内仍硬编码 `D:/Downloads`）。
- 远程托管、多用户账号体系或云端数据库。

## 5. 产品结构

JobSniper 采用本地三层目录结构，并在 `storage_layer/` 内构建「环境 - 岗位 - 用户」三大情报支柱：

```text
scraping_layer/                 # 浏览器采集、Joblens 扩展、队列监视和归档辅助脚本
storage_layer/                  # 三位一体本地核心知识库
├── personas/                   # 【用户层】用户画像、事实底稿 (master_profile)、财务与偏好约束
├── positions/                  # 【岗位层】智联、BOSS 采集归档的微观岗位 JD 与公司详情知识库
└── markets/                    # 【环境层】人口统计、宏观政经与政策、行业结构、企业财报、论文与技术前沿
session_layer/                  # 定向简历、咨询报告、面试复盘等会话交付产物
```

核心运行与决策链路：

```text
[微观岗位采集] AI Client -> MCP Server -> Joblens -> Downloads 队列 -> storage_layer/positions
[宏观环境摄入] AI Client -> 统计公报/政策/财报/论文/新闻研报检索 & 提炼 -> storage_layer/markets
[个体画像沉淀] 深度访谈 / 简历解析 / 复盘 -> storage_layer/personas
       ↓
[三维决策引擎] Environment (人口·政经·行业·财报·论文) × Position × User 交叉核验
       ↓
[交付产物] 职业战略定位 / 三维岗位推荐 / 痛点穿透型简历 / 真实场景模拟面试 (session_layer/)
```

`scraping_layer/joblens/` 是 Joblens 扩展子项目；本文档是 JobSniper 项目级 PRD。

## 6. 当前限制

- 当前采集依赖本机 Chrome 或 Edge（自动探测常见安装位置，可用 `JOBSNIPER_CHROME_PATH` 显式指定）。
- 当前 Joblens 扩展依赖浏览器登录态访问招聘平台。
- 队列与归档目录可用 `JOBSNIPER_DOWNLOADS_PATH` 配置并支持自动探测；但 Joblens 扩展内部队列路径仍硬编码，暂不支持自定义目录。
- WSL 与 Windows 文件系统之间的 `/mnt/*` 挂载权限可能影响移动归档。
- 智联安全验证/验证码需要人工处理，不自动绕过。
- 宏观与中观行业情报（财报、研报、人才断层动态）目前依赖 Agent 联网检索与结构化归档，尚待进一步沉淀自动化 MCP 工具链。

## 7. 本地环境配置化（已实现，剩余收尾）

为支持其他用户从 GitHub 下载并部署 JobSniper，本机硬编码路径依赖已移除，改为「环境变量 > 自动探测 > 默认值」。

### Downloads 路径

- 支持环境变量 `JOBSNIPER_DOWNLOADS_PATH`。
- 未设置时自动探测：`/mnt/d/Downloads` → `~/Downloads` → `/mnt/*/Users/*/Downloads` → `/mnt/*/Downloads`。
- MCP Server 会将解析结果注入监视/归档脚本子进程，保证 MCP Server、监视脚本、归档脚本路径一致。

### Chrome 路径

- 支持环境变量 `JOBSNIPER_CHROME_PATH`。
- 未设置时自动探测 Chrome 稳定版/x86 与 Edge x64/x86 的常见安装位置，以及每用户 Chrome 安装位置。
- 未探测到且路径不存在时，采集入口返回包含实际路径的错误信息。

### 剩余收尾

- 本地配置文件支持（`.env` / `jobsniper.local.json`）。
- Joblens 扩展队列路径配置化（扩展内仍硬编码 `D:/Downloads`，需 `chrome.storage` 方案）。
- Linux / macOS 原生环境的分阶段验证。

## 8. 成功标准

- **基础底座层**：
  - MCP Client 能完成 `initialize`、`list_tools` 和 `list_resources`。
  - 智联与 BOSS 直聘的 job menu、job list、job detail 采集入口可用，监视脚本自动触发归档。
  - 岗位详情可在 `storage_layer/positions` 中按自然嵌套结构保存和检索。
  - 用户画像与事实底稿可在 `storage_layer/personas` 中读取和增量更新。
  - 本地路径配置化已落地：新用户无需修改源码即可部署运行（环境变量或自动探测）。
- **三维决策与立体情报层（V2.0 标准）**：
  - 行业与企业经营情报可在 `storage_layer/markets` 中按标准 Schema 归档与复核（附来源与检索日期）。
  - 职业咨询与规划不再仅依赖静态单选题或纯文本比对，必须输出包含**行业财报/增长极、真实 HC 供求、人才结构断层**的三维推演证据链。
  - 岗位推荐、简历定制与模拟面试能够同时满足**「用户个人价值适配行业市场痛点」**与**「行业组织生态适配用户个人需求与边界」**的双向适配要求。

## 9. 风险与应对

- **工程与采集风险**：
  - 招聘平台页面结构变化会影响采集稳定性。
  - 招聘平台安全验证会中断自动化流程。
  - 浏览器扩展、MCP Server、监视脚本运行在不同上下文，路径配置必须保持一致。
  - Windows/WSL、Linux、macOS 的路径和权限模型不同，配置化方案需要分阶段验证。
- **情报失真与决策风险**：
  - **二元平面匹配误导**：若缺失环境层情报，Agent 容易将高匹配度 JD 误判为高胜率机会（忽视业务收缩、假岗位或隐性学历门槛）。应对策略：在 Skills 流程中强制设置“宏观/中观市场核验”前置门禁。
  - **市场情报时效性衰减**：企业财报、战略重心与 HC 状态随季度快速变化。应对策略：所有 `markets` 文档强制标注采集时间戳（`collected_at`）与有效期，超期触发联网复核。
